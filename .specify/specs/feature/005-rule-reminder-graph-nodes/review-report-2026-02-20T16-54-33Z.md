### 🔴 C2: TOCTOU Security Vulnerabilities in Mutation Guards

**Severity**: CRITICAL SECURITY
**Category**: Time-of-Check Time-of-Use Race Condition
**Affected Files**:
- `skills/memory/src/core/write.ts` (lines 440-469)
- `skills/memory/src/maintenance/rename.ts` (lines 182-198)
- `skills/memory/src/maintenance/move.ts` (lines 207-224)
- `skills/memory/src/maintenance/promote.ts` (lines 211-235)

**Issue**: Read-only external node guards execute **AFTER** file operations have already completed:

```typescript
// write.ts - File written FIRST, guard checked SECOND
await writeFileAtomic(filePath, fileContent);  // Line 441
await addToIndex(basePath, indexEntry);        // Line 457
// ... guard check happens here (line 463) - TOO LATE!
```

**Impact**:
- User could overwrite index entry for external nodes before guard fires
- File system mutations occur before protection kicks in
- Corrupts external node metadata in index
- **CWE-367 vulnerability**

**Fix Required**: Move all external node type checks to the **beginning** of each function, before any file I/O or state mutations.

**Estimated Effort**: 1-2 hours

### 🔴 C3: Event Loop Blocking from Synchronous File Operations

**Severity**: CRITICAL PERFORMANCE
**Category**: Node.js Best Practices
**Affected Files**:
- `skills/memory/src/external/external-file-discovery.ts` (lines 25, 38, 58, 306, 348, 354, 358)
- `skills/memory/src/search/embedding.ts` (lines 83, 88, 104, 105)

**Issue**: All file system operations use blocking synchronous APIs:

```typescript
// BLOCKS event loop during file read + hash computation
const content = fs.readFileSync(filePath, 'utf-8');  // ❌
const stats = fs.statSync(filePath);                  // ❌
const realPath = fs.realpathSync(filePath);           // ❌
fs.readdirSync(rulesDir);                             // ❌
```

**Impact**:
- CLI freezes during discovery (no responsiveness)
- With 100 files on slow filesystem: 5-25 seconds of complete blocking
- Cannot handle concurrent operations
- Poor user experience on network mounts, Docker volumes
- CI/CD timeouts possible

**Fix Required**: Convert all sync file ops to async using `node:fs/promises`:

```typescript
import * as fsp from 'node:fs/promises';

async function calculateContentHash(filePath: string): Promise<string> {
  const content = await fsp.readFile(filePath, 'utf-8');  // ✅ NON-BLOCKING
  // ...
}
```

**Estimated Effort**: 4-6 hours (includes test updates)

### 🔴 C4: Missing FR-024 Implementation (1MB File Size Limit)

**Severity**: BLOCKER (Spec Non-Compliance)
**Category**: Functional Requirements
**Affected Files**:
- `skills/memory/src/external/external-file-discovery.ts`

**Issue**: Specification FR-024 requires: *"System MUST skip external files larger than 1MB with a warning message, preventing event loop blocking during file I/O."*

No file size check exists anywhere in discovery or indexing code.

**Impact**:
- Large CLAUDE.md files (multi-megabyte) could block event loop
- Potential memory exhaustion
- Spec non-compliance

**Fix Required**:

```typescript
const MAX_EXTERNAL_FILE_SIZE = 1_048_576; // 1MB

const stats = fs.statSync(realPath);
if (stats.size > MAX_EXTERNAL_FILE_SIZE) {
  console.warn(`Skipping large external file (${stats.size} bytes): ${realPath}`);
  return;
}
```

**Estimated Effort**: 1 hour (includes test coverage)
