### H1. Missing Path Validation During External File Discovery ⚠️ SECURITY

**Severity:** HIGH
**Expert:** Security Code Expert
**Category:** Path Traversal, Symlink Following
**CWE References:** CWE-22, CWE-59

**Files Affected:**
- `skills/memory/src/external/external-file-discovery.ts` (lines 265-296, 400-437)

**Problem:**

The `isValidExternalPath()` function exists in `fs-utils.ts` (line 466) but is **not called during discovery**. Validation only happens at read-time and delete-time, meaning discovered paths are stored in `index.json` without boundary validation.

```typescript
// CURRENT: No validation during discovery
const addFile = async (filePath: string, kind: ExternalFileKind) => {
  const realPath = await resolveSymlink(filePath, visited); // Only checks loops
  const contentHash = await calculateContentHash(realPath); // No boundary check
  // ... path stored in results without validation
};
```

**Attack Scenario:**

An attacker with write access to `.claude/agent-memory/` could create a symlink pointing to a sensitive file (e.g., `/etc/shadow`, `~/.ssh/id_rsa`). The discovery phase would:
1. Read the file content for hashing (line 42)
2. Send content to Ollama for embedding generation
3. Persist the external path in `index.json`

While subsequent `memory read` operations would validate the path, the initial discovery/hash/embed cycle would have already processed the sensitive file.

**Required Fix:**

```typescript
// Add validation immediately after symlink resolution
const addFile = async (filePath: string, kind: ExternalFileKind) => {
  const realPath = await resolveSymlink(filePath, visited);

  // NEW: Validate path is within allowed boundaries
  if (!isValidExternalPath(realPath, { projectRoot, homeDir })) {
    return; // Skip files outside allowed directories
  }

  const contentHash = await calculateContentHash(realPath);
  // ... rest of function
};
```

### H2. Null Byte Handling Test Asserts Incorrect Behaviour ⚠️ SECURITY

**Severity:** HIGH
**Expert:** Security Code Expert
**Category:** Null Byte Injection
**CWE Reference:** CWE-158

**Files Affected:**
- `skills/memory/src/core/fs-utils.spec.ts` (lines 590-594)
- `skills/memory/src/core/fs-utils.ts` (line 474)

**Problem:**

The test asserts that paths containing null bytes (`\0`) are valid:

```typescript
it('should handle null byte in path (normalized by path.resolve)', () => {
  const result = isValidExternalPath('/home/user/project/file.md\0', { projectRoot, homeDir });
  expect(result).toBe(true); // ❌ INCORRECT ASSERTION
});
```

The comment claims `path.resolve()` strips null bytes, but **this is false**. In Node.js, `path.resolve()` passes null bytes through unchanged. On Linux, the kernel treats null bytes as string terminators, so `open("/path/file.md\0injected")` actually opens `/path/file.md`, bypassing extension checks.

**Required Fix:**

```typescript
// In fs-utils.ts, add explicit null byte check:
export function isValidExternalPath(externalPath: string, options: PathValidationOptions): boolean {
  // NEW: Reject null bytes explicitly
  if (externalPath.includes('\0')) {
    return false;
  }

  // ... existing validation logic
}

// Update test to assert rejection:
it('should reject paths containing null bytes', () => {
  const result = isValidExternalPath('/home/user/project/file.md\0', { projectRoot, homeDir });
  expect(result).toBe(false); // ✅ CORRECT ASSERTION
});
```

**Priority:** 🔴 **HIGH - Security**

### M3. Mermaid/DOT Output Injection Risk 🔐 SECURITY

**Severity:** MEDIUM
**Expert:** Security Code Expert
**Category:** Output Injection
**CWE References:** CWE-79, CWE-74

**Files Affected:**
- `skills/memory/src/graph/mermaid.ts` (lines 501-503, 147-156)

**Problem:**

`generateDot()` directly interpolates `node.id` into DOT output without escaping:

```typescript
lines.push(`  "${node.id}" [label="${label}"];`);
```

While `escapeLabel()` sanitises label content, **node IDs are not sanitised** before being placed in double-quoted DOT strings. If a node ID contained a double quote, it could break out and inject arbitrary DOT commands.

**Impact:**

Low for local CLI usage, but if rendered in a web UI, this could lead to XSS or misleading diagram rendering.

**Recommended Fix:**

```typescript
const sanitisedId = sanitiseId(node.id);
lines.push(`  "${sanitisedId}" [label="${label}"];`);
```

Also add backtick escaping to `escapeLabel()` for Mermaid special syntax.
