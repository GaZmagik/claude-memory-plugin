# Implementation Plan: Rule and Reminder Graph Nodes

**Branch**: `feature/005-rule-reminder-graph-nodes` | **Date**: 2026-02-19 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `.specify/specs/feature/005-rule-reminder-graph-nodes/spec.md`

## Summary

Add support for indexing two categories of external Claude CLI files as read-only graph nodes in the memory knowledge graph. Implements two new MemoryType values (`rule` and `reminder`) to make CLAUDE.md, rules/*.md, and agent MEMORY.md files discoverable through semantic search, linkable to memories, and visible in graph visualisations. This enables agents to understand the full context of what governs their behaviour (rules) and what they carry between sessions (reminders), whilst maintaining strict read-only semantics to prevent corruption of Claude CLI-owned files.

**Language/Version**: TypeScript 5.3 (Bun runtime)
**Primary Dependencies**: Bun, Ollama (optional - graceful degradation), existing memory plugin infrastructure
**Storage**: JSON files (graph.json, index.json, embeddings.json) - no schema changes, only field additions

**Performance Goals**:

- Index refresh via `memory index-context`: <5s excluding embedding generation
- No performance degradation to existing `memory sync` workflow
**Constraints**:
- Read-only semantics: External files MUST never be modified by plugin
- Backward compatibility: Existing memories must function unchanged
- Graceful Ollama fallback: Indexing succeeds even if embeddings unavailable
**Scale/Scope**:
- Typical project: 5-10 rule files, 2-5 agents with MEMORY.md files
- Large project: 20+ rule files (ancestor CLAUDE.md files), 10+ agents
- External file sizes: Up to 100KB (truncated to 6000 chars for embedding)

## Phase 0: Research

See [research.md](./research.md) for full research findings.

**Key Decisions**:
1. **Two MemoryType values (rule + reminder)** - Preserves semantic distinction between prescriptive (rules govern behaviour) and descriptive (reminders carry state). Enables distinct graph edges (governed-by vs reminded-by) and visual representation (hexagon vs cylinder).
2. **Extend IndexEntry with optional fields** - Backward compatible approach. Two optional fields (externalFileKind, externalPath) vs creating separate ExternalIndexEntry interface that would require union types throughout codebase.
3. **Reuse existing embedding pipeline** - truncateForEmbedding() already handles large files (6000 char limit). Content-hash cache invalidation detects changes. No modifications needed.
4. **External file indexer as final sync pass** - Additive operation after orphan cleanup. Failed discovery doesn't corrupt user data.
5. **Deterministic ID generation** - Stable IDs (rule-project-claude-md, rule-ancestor-2-claude-md, reminder-project-curator-memory) ensure consistency across syncs. Canonical path resolution for symlinks.

**Architecture Overview**:

```
┌─────────────────────────────────────────────────────────┐
│ External File Discovery (external-file-discovery.ts)    │
│ - Walk directory tree (cwd → home)                      │
│ - Scan rules/ directories                               │
│ - Enumerate agent-memory/ directories                   │
│ - Generate deterministic IDs                            │
│ - Filter vendor paths                                   │
└────────────────┬────────────────────────────────────────┘
                 │ ExternalFileEntry[]
                 ↓
┌─────────────────────────────────────────────────────────┐
│ External File Indexer (external-file-indexer.ts)        │
│ - Upsert nodes to graph.json                            │
│ - Upsert entries to index.json                          │
│ - Generate embeddings via existing pipeline             │
│ - Content-hash based cache invalidation                 │
└────────────────┬────────────────────────────────────────┘
                 │ Updates graph/index/embeddings
                 ↓
┌─────────────────────────────────────────────────────────┐
│ Sync Integration (maintenance/sync.ts)                  │
│ - Run external indexer as final pass                    │
│ - Report changes (addedExternalNodes)                   │
└─────────────────────────────────────────────────────────┘
```

**Data Flow**:
1. User runs `memory sync` or `memory index-context`
2. Discovery scans known paths → ExternalFileEntry[]
3. Indexer reads file content, generates ID, determines scope
4. Checks cache: if content hash matches, reuse embedding
5. If hash differs or missing, generate new embedding via Ollama
6. Upsert to graph.json (GraphNode with type rule/reminder)
7. Upsert to index.json (IndexEntry with externalPath field)
8. Save embedding to embeddings.json

**Read-Only Enforcement**:
- cmdWrite: Check node.type === 'rule' || node.type === 'reminder' → reject
- cmdDelete: Same check → reject with message "Run 'memory sync' to refresh it"
- cmdRename: Same check → reject
- cmdMove: Same check → reject
- cmdPromote: Same check → reject
- cmdRead: Handle externalPath field (read from external location, not basePath)

## Risks & Mitigation

| Risk | Impact | Probability | Mitigation |
|------|--------|-------------|------------|
| Directory tree walking performance on deep hierarchies | Medium - Sync slowdown | Low | Vendor filtering (skip node_modules/, .git/), early termination at home directory, canonical path caching |
| Symlink loops causing infinite recursion | High - Sync hangs | Low | Track visited canonical paths in Set, skip if already visited |
| Race condition: CLAUDE.md modified during sync | Low - Stale embedding | Medium | Content hash detects staleness on next sync. Acceptable eventual consistency. |
| Large CLAUDE.md files (>100KB) causing memory issues | Low - OOM | Very Low | truncateForEmbedding() limits to 6000 chars (~1500 tokens). Existing safeguard. |
| Ollama unavailable during sync | Low - No embeddings | Medium | Graceful fallback: nodes indexed without embeddings. User runs `memory index-context` after Ollama restored. |
| ID collisions from deterministic generation | High - Node overwrite | Very Low | Comprehensive ID scheme testing. Use path components (ancestor-N, project, global) for uniqueness. |
| Breaking existing memories during IndexEntry extension | High - Data corruption | Very Low | Optional fields maintain backward compatibility. Existing memories never have externalPath set. |
